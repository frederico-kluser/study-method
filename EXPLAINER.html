O que foi entregue, segmento por segmento

1. install.sh — destino local

SKILLS_DIR passou a ter default <repo>/.claude/skills/ (skills de projeto do Claude Code). O override CLAUDE_SKILLS_DIR continua funcionando igual. A lógica idempotente e as guardas existentes foram preservadas intactas. O chmod 700 foi removido porque o destino agora é local ao repo. Resultado líquido: nenhuma escrita fora do repositório.

2. run.sh — bootstrap direto do app

Parou de chamar o install.sh. Nova sequência: valida node/npm ≥ 22.13 → cria app/.env.local se faltar → roda HUSKY=0 npm --prefix app ci apenas se node_modules estiver incompleto (e aí escreve o marcador .install-ok) → exec app/run-dev.sh. A ordem .env.local antes de npm ci foi explicitamente preservada e verificada na revisão adversarial. Nunca instala skills, em nenhuma circunstância.

3. Skills globais existentes — intocadas

Nada em ~/.claude/skills/ é removido, movido ou modificado. A propriedade está comprovada pelos testes executando os scripts com HOME falso: se o script tentasse escrever fora do repo, o teste veria a escrita no falso HOME e falharia.

4. Documentação atualizada

README (instalação local, seção "À mão" local, precedência pessoal > projeto, nota de que globais existentes ficam), docs/01-arquitetura.md, docs/app-gui.md §2.17, docs/11-seguranca-privacidade.md, docs/00-contratos.md, docs/build-spec/20-skill-md.md + blocks 00/07/08 e BUILD_SPEC.md — todos alinhados ao novo comportamento.

5. CI e testes

O job install do .github/workflows/gate.yml foi adaptado para usar override CLAUDE_SKILLS_DIR, rodar provas de isolamento e incluir um passo que demonstra o default local. Novo arquivo de teste runsh-bootstrap.test.ts cobre a guarda de fonte e a execução com stubs (prova tripla: nada em CLAUDE_SKILLS_DIR, nada em <repo>/.claude vindo do run, nada em $HOME/.claude).
